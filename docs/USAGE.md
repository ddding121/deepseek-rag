# DeepSeek RAG V3：混合检索、重排序与结构切块

本版本承接 V2，保留持久保存、OCR 和文档管理，增加 BM25+语义混合检索、可选 BGE 重排序、段落/句子/标题切块，以及保存原文重建入口。

## 一、从已跑通的 V2 升级（Windows CMD）

1. 原 CMD 按 Ctrl+C 停止网站，备份原代码。
2. 将本包全部内容复制进 D:\deepseek-rag，同名源码覆盖。
3. **不要删除原 .venv、.env 或 data 文件夹。** 包内不含这三个目录/文件。
4. 使用原虚拟环境，执行 `python -m pip install -r requirements-retrieval.txt` 安装重排序分词依赖。
5. 启动：

```bat
cd /d D:\deepseek-rag
.venv\Scripts\activate.bat
python -m streamlit run app.py --server.maxUploadSize 50
```

也可以双击 start.bat 启动。V2 的 data/knowledge.db 可以直接读取，无需重新上传。先下载备份，再在文档管理中展开“升级旧知识库”，用已保存原文件重建；重建成功后启用 V3 切块。若你仍在无持久化的 OCR 旧版，则需要重新上传一次资料。

## 二、使用步骤

1. 在左侧新建知识库，如“课程资料”。中文向量模型默认保持不变。
2. 在“文档管理”选择 OCR 模式、上传文件，点击“处理并保存到知识库”。
3. 在“知识问答”填写 API 密钥并提问，展开引用核对原文。
4. 停止程序，再次启动，选择同一个知识库；之前的资料和索引仍在，无需重新 OCR 或生成正文向量。
5. 问题仍需调用向量模型生成问题向量，首次问答会加载模型；生成答案仍需 DeepSeek 网络请求。
6. 后续上传新文件时，只处理新文件。相同名称、内容与解析设置的文件会跳过。
7. 修改文档后，以原文件名上传并勾选“允许替换同名文档”。内容或 OCR 设置变化都会重新处理该文件。
8. 原文列表提供已识别文字查看、原文件下载和删除；删除须勾选确认。删除、替换和切换知识库会清空当前聊天记录和内存索引，避免显示旧来源。

同名判断忽略大小写。相同内容使用不同文件名上传，视为不同文档，不做跨文件名去重。
不提供知识库重命名/删除按钮，目前可新建、切换知识库和删除库内文档。

## 三、保存与备份（重要）

数据存放在项目目录的 `data/knowledge.db`，一个数据库保存全部知识库的原文件、提取文字、OCR 提醒及向量。
路径以 app.py 所在目录为准，不随 CMD 当前目录改变。API 密钥和聊天记录不会写入数据库。

“备份与恢复”页点击“生成全部知识库备份”，再点击下载。
请存到项目目录之外，例如 E:\RAG备份。**本地持久保存不能防止你删除整个项目文件夹。**

恢复：

1. 停止所有运行此项目的程序。
2. 先把现有 data 文件夹复制一份保留。
3. 将下载的 knowledge-backup.db 复制到 data，重命名为 knowledge.db，替换原数据库。
4. 重新启动。恢复是替换全部知识库，不是合并。只使用本项目生成的可信备份。

SQLite 备份 API 生成一致快照。更新资料采用整批事务：解析、OCR、向量生成或配额检查失败都不覆盖旧库。
多个窗口同时更新时，版本检查会拒绝旧版本覆盖，提示刷新重试。

## 四、原有能力与限制

- PDF、DOCX、PNG、JPG、JPEG、BMP、WEBP；扫描 PDF 和 Word 内嵌位图 OCR。
- 每个知识库最多 10 个文件、原文件合计 50 MB、10000 片段；单 PDF 最多 400 页。每次上传也限制 10 个、合计 50 MB。
- 数据库会额外保存文字、向量和 SQLite 空间，实际数据库大小可能超过原文件的 50 MB。
- OCR 自动模式只处理文字少的页。图文混排可选全页 OCR；400 页可能耗时较长。
- OCR 执行在本机，提问时仅问题和检索文字等发送到 DeepSeek；不向 DeepSeek 发送原图。
- OCR 不理解照片或图表关系；文字识别可能错误，复杂表格和公式需要核对。
- 向量模型名称在创建知识库时固定。不要替换本地模型路径下的权重；更换模型应新建库重建，避免混用不兼容向量。
- 本次加入混合检索、可选 reranker 和结构切块。连续追问、PDF 页内高亮、OCR 断点续传尚未加入。
- 这是本地单用户应用，多个知识库只做数据分组，不等于多用户权限隔离。仍绑定 127.0.0.1。
- 聊天记录仅保存在当前会话内存，不跨重启保存。

## 六、代码结构

- app.py：页面、知识库切换、增量导入、问答、删除和备份入口。
- storage.py：SQLite 数据表、事务、版本冲突检测、原文/向量保存和备份。
- ingestion.py：比较文件哈希与 OCR 配置，仅处理变化文件，整批提交。
- rag.py：文档/OCR 解析和 DeepSeek 调用，保留旧 retrieve 接口供对照测试。
- retrieval.py：BM25 关键词索引、语义候选、RRF 融合、可选 CrossEncoder 重排。
- chunking.py：段落/句子打包、短标题前缀保留和来源边界处理。
- ocr_engine.py：原有本地 RapidOCR 引擎。
- tests：核心解析测试、持久化与增量测试、Streamlit 页面交互测试。

## 九、V3 检索说明与使用建议

1. 默认选择“混合检索”，从关键词 BM25 和语义两路各取候选，以 RRF（k=60）融合。候选上限为 max(20,4×最终片段数)，最多等于库内片段数。
2. BM25 使用中文相邻双字、英文词和型号词元，不依赖在线分词服务。它有利于精确词匹配，但不是完整中文语言理解；常见词重叠也可能误召回。
3. “语义候选最低相似度”只限制语义分支；BM25 正分片段仍可补入。因此混合结果中出现低于阈值的语义分是预期行为。
4. 重排序默认关闭。勾选后首次下载 BAAI/bge-reranker-base，以问题与候选片段成对计算分数；CPU 会更慢，需要额外内存和磁盘空间。关闭不影响混合检索。
5. 如重排序模型下载或依赖失败，本次问答会报错；可以取消勾选继续混合检索，不会静默假装重排序成功。
6. 引用展开区分别展示余弦相似度、BM25、RRF 和重排分。各分数尺度不同，都不是答案可信度，不能直接互比。
7. 默认每块最大 350 字符，在段落/句子边界打包，超长句才硬切并重叠 50 字符。数字章节、Markdown 标题和 Word Heading 样式可携带标题上下文。
8. Word 相邻正文段落合并时，来源显示对应段落范围；不会虚构 Word 页码。PDF 不跨页合并，也不声称恢复 PDF 的完整层级结构。
9. 旧索引立即可用混合检索。结构切块只有新上传/重建的文件生效；重建会重新 OCR 和生成正文向量，但仅在整批成功后替换旧索引。
10. 即使已经是 V3，也可以强制重建；支持失败回滚与版本冲突检测。没有 OCR 断点续传，长文档请耐心等待。

## 十、验证范围

交付环境通过 24 项自动化测试：原解析/保存/页面测试，加上关键词补召回、无候选、模拟重排序、重复片段去重、标题切块、长文覆盖及旧库重建。
这些检索测试使用固定向量和模拟重排分，验证逻辑，不代表真实模型准确率。未下载运行真实 BGE 重排序权重，未进行 DeepSeek API 端到端调用，不宣称准确率提升百分比。

建议使用同一份资料准备 20–30 道真实问题，包含专业术语/型号、同义改写、跨段问题和资料无答案问题。对比“仅语义”“混合”“混合+重排”，记录原文是否命中及答案是否有依据。

重排序官方来源：https://huggingface.co/BAAI/bge-reranker-base
CrossEncoder API：https://sbert.net/docs/package_reference/cross_encoder/model.html


## V3 原布局 + 低相似度提醒

此包从原始 V3 构建，保留其页面和功能，没有 V3.1 的检索预览、并排对比、诊断面板、设置快照和重新回答按钮。唯一新增：每次回答上方，如果全库最高语义相似度严格低于本次阈值，则显示黄色提示，建议核对原文后适当降低阈值并重新发送问题。混合模式关键词有命中时也会提醒。阈值不会自动修改。

从 V3/V3.1 升级或回退：停止程序，仅覆盖此包中的 app.py 和 retrieval.py 即可；其他新增诊断文件即使留在目录也不会被调用。保留 .venv、.env、data。不安装新依赖，不重建已有 V3 索引。刷新页面并重新提问查看提醒。历史结果不随参数切换重新计算。
